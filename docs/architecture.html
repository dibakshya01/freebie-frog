Architecture

Three diagrams, one honest machine.

The component pipeline, the streaming translation that is the hard part, and where the security guards actually sit.

A — Component pipeline

From agent to provider, and back.

A request enters in the Anthropic Messages API, is routed and translated inside freebie-frog, and leaves through a single SSRF-guarded HTTP client to the provider you chose.

ingress / your side egress / provider side security boundary

Responses return the same way. The adapter streams provider chunks back through Translate, which rebuilds the Anthropic SSE sequence, out through ingress to the agent. Upstream base URLs are treated as attacker-influenced input — hence the guard on every outbound call.

B — Streaming translation

Rebuilding the Anthropic event stream, in order.

The core mechanic. Provider chunks arrive loosely; the Anthropic SSE sequence must be emitted in a strict order, with tool-call arguments accumulated defensively by index.

Fallback has a hard boundary. The router may retry another provider only before event 1 is sent. Once message_start is out, a mid-stream upstream failure cannot be retried transparently — the proxy emits an Anthropic error event and a terminal message_stop. This path is covered by golden SSE snapshot tests.

C — Security placement

Where the guard and the secrets sit.

Keys are resolved from a backend by reference and scrubbed from every log. Every outbound dial is IP-validated, so a hostile or mistaken upstream can't reach loopback, private ranges, or cloud metadata.

resolved key / allowed guard / blocked

The local-model opt-in is scoped, not a bypass. allow_local permits one configured host (say Ollama on loopback); the dialer still refuses any other resolved IP, which also defeats DNS rebinding. Mapped to OWASP API7 (SSRF), LLM02 (secret disclosure), and API8 (secure defaults).

Design principles

The trade-offs are decided in advance.

Five principles resolve the hard calls — and they are why the honest limits read the way they do.

Protocol correctness first

The streaming SSE translation is the product. It's snapshot-tested against spec fixtures and an in-process mock, and verified against a real agent loop where credentials allow.

Security by default

Keychain secrets, no secret logging, loopback bind, and the SSRF guard are on from the start — wired in, not bolted on, and proven with attack-tests.

One binary, few deps

Go stdlib-first; a single optional keychain library, everything else from the standard library. The static binary is the distribution wedge — no runtime to install.

Honest & ToS-respecting

BYO-key, single-account. No quota evasion, no account rotation. Claims match measured reality; the project is clean-room and trademark-clean.

Config-driven breadth

One generic OpenAI-compatible adapter plus a per-provider config row covers the field; a native Gemini adapter is the one extra. Runtime model discovery is preferred over hard-coded rosters, because free tiers churn constantly.

Honest limits, by design. Token counts are approximate; not every Anthropic feature maps (prompt caching, server-side tools, fine-grained thinking budgets); provider parity varies; mid-stream failures aren't transparently recoverable; and this is a local single-user tool, not a multi-tenant security boundary.
