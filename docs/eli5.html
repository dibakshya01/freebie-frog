Explain it simply

A universal adapter for your coding assistant.

No jargon. If you lead a team that uses AI coding tools — or you just want the gist — this page is for you.

Like a travel power adapter.

Your laptop charger is built for one kind of socket. Take it abroad and it won't fit the wall. An adapter sits in between so the same charger works anywhere. freebie-frog is that adapter — your coding assistant plugs into one shape, and freebie-frog makes it fit any model provider's socket.

And a live translator.

Your assistant and the model speak different dialects. freebie-frog translates both ways in real time — question into the model's language, answer back into your assistant's — so neither side notices anyone translated. It even keeps the answer streaming word-by-word, the way you expect.

Why it exists

Your AI coding tool is usually tied to one company's models.

Choice. Run the same assistant on a free model, a model on your own laptop, or a paid one — whichever fits the moment.

Cost. Everyday work can lean on free tiers or local models, so the bill from any one provider stays small.

Reliability. If one free service is busy, it automatically tries the next one you've listed, so you keep working.

Privacy. Point it at a model running on your own machine and nothing leaves your computer.

How you'd set it up

Three steps, on your own computer.

Install the small program

It's a single file — no big install, no extra software to keep running. (Your developer runs one command; see the docs.)

Add the keys you already have

You bring your own free or paid accounts with the model providers. freebie-frog stores those keys safely and never prints them in its logs.

Tell your assistant to use it

One setting points the coding assistant at freebie-frog instead of the default. From then on, it just works — on whichever model you chose.

The honest part

What it is not.

The whole point of this project is to be straight with you. So:

Not "unlimited free AI."

Across providers you can expect, honestly, on the order of tens to hundreds of millions of free tokens a month — real, but capped by each provider's per-minute and per-day limits, and those change whenever the providers decide. It is not a bottomless bucket.

Not a loophole.

It uses your own single account with each provider. It deliberately will not juggle multiple accounts or pool quotas to dodge limits — that breaks providers' rules, and respecting them is a design choice.

Not identical on every model.

Different models have different abilities, and token counts are estimates. Most things carry across cleanly; a few advanced features don't map perfectly and are approximated or skipped.

Not a shared server.

It's a personal tool that runs on one person's machine. It isn't built to be a locked-down service for lots of untrusted users.

If you're the one deciding

Talking points for leaders.

What you can say with confidence

It's open source under Apache-2.0, with a clear patent grant — safe to evaluate and adopt.

Security came first: it guards against a common class of server attack, protects stored keys, and stays on the local machine by default.

It respects providers' terms of service — no quota evasion, no account juggling.

It can keep sensitive work fully local by routing to an on-machine model.

What to set expectations on

"Free" is real but limited and provider-dependent — plan for paid fallback on heavy days.

Output quality tracks the model you pick — a small free model won't match a frontier one.

It's an early-stage, community project in active development — evaluate before anything mission-critical.

Review each provider's data and privacy terms before sending them company code.
