Think back to the week you first wired a model into something real. Not a weekend demo, but a feature with a user on the other end of it. You shipped a chat box, or a summariser, or a small agent that could fetch a thing and then act on it. It worked. It was, frankly, a delight. And then a day or two later, usually in the shower or halfway to sleep, a cold little question arrived uninvited. What happens if someone simply tells it to ignore everything I wrote?

You went looking for an answer, as any sensible person would. You reached for the security tools you already trusted, the linters and scanners that had guarded your code for years, and you found a quietly alarming truth. They see none of it. Not the prompt injection, which needs no password and is the single most common AI attack there is. Not the agent that will take an irreversible action on one poisoned instruction. Not the MCP tool whose description rewrote itself overnight. Your whole trusted toolbox was built for a world that no longer quite exists, and it was looking straight through the new attack surface as though it were glass.

So you tried the next thing, and here the situation turns properly absurd. The tools that do claim to secure AI features tend to want an AI of their own to do it. They ask for an API key. They stream your source code off to a model somewhere and wait for a ruling. The ruling costs money. It changes between runs, because the model changed its mind. And the one piece of software you were hoping would keep your code private has just posted it through a stranger's letterbox.

That is a strange state of affairs. A security scanner, of all things, that flakes, that bills you by the scan, and that cannot keep a secret. A gate your team will quietly learn to ignore the third time it blocks a clean build for no reason anyone can reconstruct.

The real problem is not that you lack a scanner. It is that security for AI code quietly became non-deterministic, and a non-deterministic guard is barely a guard at all. You cannot build a discipline on a verdict you cannot reproduce.

So I built Grey Panda. It is a zero-dependency, standards-anchored AI security toolkit you can run in seconds, in your editor, in your CI pipeline, or straight from the terminal. It finds the AI, agent, and MCP problems your old tools miss, and it never once calls a model to do its job.

pip install grey-panda        # pure Python, zero dependencies
gp scan .                     # real findings, a verdict you can reproduce

The engine underneath is deliberately, almost proudly, dull. It is pure Python standard library, regular expressions and the `ast` module, and nothing else. There is no package to install beside it, nothing new in your supply chain, no network round-trip. Same code in, same verdict out, every run, forever. Your CI gate stops flaking because there is nothing left in it to flake. Your source never leaves the machine, which ought to be the least surprising property a security scanner could have and is somehow the rarest.

Adding the runtime guardrails to an existing model call takes about two minutes, and you never rewrite the call. You wrap it.

from greypanda import PromptGuardrail, DLPScanner, OutputGuardrail

guard, dlp, out = PromptGuardrail(), DLPScanner(), OutputGuardrail()

safe   = guard.assert_safe(user_input)        # block known injection, strip invisible Unicode
clean  = dlp.redact(safe)                      # remove PII and secrets before the model sees them
reply  = call_your_llm(clean)                  # your existing call, untouched
answer = out.sanitize(reply).sanitized_text    # HTML-escape the output, XSS-safe

Allow me one paragraph of respect for the part that was genuinely hard, because it is where the real work went. Spotting a hardcoded key with a regex is a parlour trick. The difficult thing is following tainted data. When a model's output flows into a variable, and that variable is handed, three lines later, into a SQL query or a server-side HTML render, that is the bug that actually hurts, and a line-by-line pattern match sails right past it. So Grey Panda carries a small function-scoped taint tracker, built on Python's own `ast`, that follows model-tainted variables into the highest-impact sinks and raises its hand when one lands somewhere dangerous. It is honest about its own reach, holding to a single function and to Python alone, but within those walls it catches the class of mistake that costs you a weekend. That quiet bit of machinery is finished, and it earns its keep.

Now the part where I disappoint you a little, on purpose, because it is the most important thing here. Grey Panda will not stop all prompt injection. Nothing will. NIST, the NCSC, and OWASP all say so plainly, and a tool that pretends otherwise is selling you a feeling. Its pattern matching catches exact known phrasings and lets a clever paraphrase through. Its data-loss redaction is tuned to specific languages and formats, and unusual ones slip past it. Its scanner is static, so it reads your code and never watches it run, and it leans towards Python, with only partial cover for everything else. It will raise the occasional false alarm and miss the occasional cleverly obfuscated one.

I am not burying any of that. Grey Panda ships a whole document called WHAT_IT_CAN_AND_CANNOT_DO, and it lists, for every single capability, a confidence level and the exact condition under which it fails. If a control is not marked high confidence there, you should not stake your production system on it alone. I would rather you trust the tool a little less and understand it a great deal more, because a floor you can measure is worth more than a ceiling somebody painted on the sky.

A word on the tool's own hygiene, since we are being plain. Every rule, checklist item, and control cites a specific published identifier from OWASP, AISVS, ACS, or the MCP work, so a finding is something you can read, argue with, and look up, never an opaque judgement from a model you cannot question. It emits SARIF 2.1.0, so your findings land in the IDE and in GitHub code scanning where you already look. It scans itself clean on its strictest profile in its own continuous integration. And it is deterministic by design, which means the thing standing between a pull request and production stays boring and predictable, exactly as a gate should.

What is it all for, underneath? Blast radius, mostly, which is a quieter idea than prevention and a far sturdier one. You will not build a model that cannot be fooled. So you build the system around it with enough care that when the model is fooled, and one day it will be, nothing important breaks. You quarantine the data. You give the agent the least power it can do its job with. You make every action auditable. You put a human in front of anything irreversible. Grey Panda's single ambition is to make that secure path the easy path, the one a tired developer takes at five on a Friday because it is simply less effort than the dangerous one.

It is Apache-2.0, free, offline, and private. It ships as an MCP server too, so the assistant already in your editor can call it and hand you reproducible, cited findings while you work. It does one awkward job properly and tells you the truth about the parts it cannot reach.

That honesty is the whole point of it. It turns out to be the most useful thing about the tool.
